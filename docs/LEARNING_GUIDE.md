# 上新图学习与面试讲解指南

## 一次完整操作发生了什么

1. 用户在上传页调用微信 `wx.chooseMedia`，得到手机中的临时图片路径。
2. 页面把名称、价格、卖点和临时路径暂存在 `App.globalData.draft`。
3. 模板页通过 `services/api.js` 请求后端模板接口；若本机后端没启动，则展示内置兜底模板。
4. 点击制作后，前端读取原图二进制，发送到 `POST /api/images`，后端限制 5MB、检查 PNG/JPEG 签名，并以随机 ID 保存到磁盘。
5. 前端将图片 ID、名称、价格、卖点、模板和比例发送到 `POST /api/generations`。后端检查原图存在，返回 `ready_for_render` 排版配置，并暂存在内存 Map；这个状态不代表图片已制作完成。
6. 预览页读取本地原图，用 Canvas 按配置排版三张 PNG，生成临时文件供预览和保存。真正的像素排版在客户端，不是后端 AI 生成；后端还不存成片。
7. 用户可以把三张临时 PNG 收藏到本地作品库；`services/local-data.js` 负责草稿、作品元数据、文件持久化和最多六套的清理规则。这里仍是设备本地存储，不是数据库或云同步。

## 面试时可以怎么讲

一句话版本：这是一个前后端分离的微信小程序 MVP，前端使用原生小程序框架，后端使用 Node.js REST API；我先用模拟生成任务验证核心用户流程，再逐步替换成对象存储、数据库和异步 AI 任务。

可以展开的技术点：

- 分层：页面不直接拼网络请求，统一由 `frontend/services/api.js` 管理地址和协议。
- 数据契约：前后端用 JSON；服务端不信任客户端输入，会校验模板 ID 与图片比例。
- 异步思想：真实图片生成耗时较长，未来创建接口应返回 `queued`，前端轮询查询接口直到 `completed` 或 `failed`。
- 失败处理：后端没启动时模板仍可浏览，但制作会失败并允许重试，不会伪造成功。上传失败不会继续创建排版任务。
- 当前局限：任务只在内存中，重启后消失；原图在本机磁盘中，无鉴权/存储配额/自动清理，不能直接暴露公网。成片导出和权限仍需微信真机验证。

## 你应该亲手理解的文件

- `frontend/pages/upload/upload.js`：微信选图、表单状态和页面跳转。
- `frontend/services/api.js`：前后端连接点。
- `backend/src/app.js`：路由、参数校验和 HTTP 状态码。
- `backend/src/store.js`：当前的内存数据层，以后会换数据库。
- `backend/test/api.test.js`：自动测试如何证明关键行为没有被改坏。

## 下一阶段的合理升级顺序

1. 先在微信开发者工具和真机验证现有交互。
2. 图片上传已有本地实现；下一步根据需要迁移对象存储，并补齐鉴权、文件解码校验与保留策略。
3. 接入一个图片处理/生成服务，使用排队任务避免请求超时。
4. 用数据库保存用户、作品和任务状态。
5. 最后再做登录、额度、订单和支付；这些涉及合规与真实资金，不应在核心价值未验证前抢跑。
